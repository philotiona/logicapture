# Logicapture — current product brief

This brief supersedes the original game-and-benchmark-oriented interface specification. The current direction follows the user's request to remove the Akinator sections and simplify the application.

## Purpose

Read contrasting visual examples, infer a separating rule, explain the observed evidence, and construct new drawings that satisfy or violate that rule. The distinctive contribution is the connection between pixel perception, an executable program and verified generation.

The product does not claim universal visual reasoning, and a classification boundary is not presented as recovery of a logical rule.

## Workspaces

| Workspace | User's goal | Main actions |
|---|---|---|
| Bongard, the opening screen | Find and inspect a visual rule | Add problem → check groups → Find the rule |
| Print Inspector | Find print defects from a camera photo | Select an accepted card → take or upload a photo → inspect the overlay |
| Local Lab | Generate a drawing from a locally learned contrast | Add examples → learn and make a drawing → test an independent drawing |
| Sort images | Apply a learned two-group distinction to personal images | Teach groups → Sort these images → review and download |
| РГР coursework | Complete the separate model-testing assignment | Photo experiments, adaptation and assignment reports |

The game and experiment dashboard have no application routes. Their historical research records are not product instructions. Shared scene generators and rule engines remain because the Bongard workflow uses them to construct examples and counterexamples.

## Bongard policy

- Accept a complete static page or separate A/B images, plus three curated example problems.
- Use all 3–8 given drawings per group. Independent test drawings are added after inference.
- Trace supported paths and regions automatically. If necessary, try the validated numeric measurement rules.
- Require the existing support-only rule checks. Retain alternatives and require agreement for a new-image decision.
- Run no optional image encoder or language model in the Bongard product flow.
- Show a plain explanation and automatically generate the two new drawings. Re-read generated pixels against every retained program.
- Mark a failed search as unsolved. Never rename a similarity prediction or a language-model hypothesis as a recovered rule.
- Keep correction of a page's divider/count available only beside that actual input. Remove algorithm and benchmark controls.
- Invalidate stale results when source pixels, group membership or page crops change. New query images never select the fit.

## Acceptance

The opening screen contains no game, experiment dashboard, inference-mode selector, representation selector, optional language model, CNN tuning, depth control or evaluation holdout switch. A novice can reach a complete result with **Try an example → Find the rule**.

The supplied arrow regression must recover along-path direction from pixels, use all twelve drawings, generate two new checked images and classify additional drawings without refitting. Boundary geometry examples and uploaded complete pages must use the same route. Unsolved inputs must not acquire a fake explanation or feature-score result. Sorting and coursework must remain independently usable.

## Limits

The rule grammar and drawing perception remain bounded. Agreement on supports does not prove uniqueness or intended meaning. The saved development coverage audit, including wrong accepted answers, remains part of the evidence. Expanding automatic rule coverage is separate work from simplifying the product interface.
